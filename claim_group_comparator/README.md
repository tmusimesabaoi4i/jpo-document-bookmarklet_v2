# claim_group_comparator — 請求項グループ比較

「書類比較・クレームチェッカー」の解析結果から請求項を取り出し、**比較候補のグループ**を自動で作って、
別タブで並べて見比べるブックマークレットです。完全にブラウザ内で動作し、外部にデータを送信しません
（依存パッケージなし。開発ツールは Node.js 18 以降のみ）。

請求項の意味を理解して「法的に同一の請求項」を判定する道具ではありません。字面・段落構造・
請求項カテゴリー・引用関係・クレームツリー上の位置が似ている請求項を**広めに束ね**、
その中の細かな文言差（主体・送信/受信・同じ/異なる・トリガ条件・カテゴリー・引用先・構成要件の増減）を
**人が見つけるため**の道具です。

## 2 つの版

**請求項のグループ分けはどちらも自動**です。違うのは「グループ内で、どの段落とどの段落が対応するか」の決め方だけ。

| | 自動関連付け版 | 手動関連付け版 |
|---|---|---|
| ブックマークレット | `src/bookmarklet/comparator.bookmarklet.js` | `src/bookmarklet/relations.bookmarklet.js` |
| ボタン文言 | 請求項グループ比較を開く | 請求項グループ比較を開く（段落関連 手動） |
| 段落の対応 | 選んだ段落に**最も対応する段落**を自動で強調（`segmatch.js`） | 利用者がチェックした段落だけを「関連」として保持（自動推定なし） |
| 初期状態 | 段落を選べばすぐ対応が出る | **関連 0 件**。作るまでどの段落も関連付かない |
| 段落の単位 | 選択した 1 段落（＋自動で見つけた対応先） | 「関連」= グループ内で対応すると判断した段落の集合。1 グループに何個でも |
| 保存 | なし（タブを閉じるまで） | **JSON で書き出し・読み戻し**（置換／追加） |

自動版が「まず当たりを付けたい」とき、手動版が「対応を自分で決めて残したい」ときの道具です。
両方を同じページで起動しても、ボタンも比較タブも互いに干渉しません。

## クイックスタート

1. 使う版のブックマークレットの**中身を1行そのまま**コピーし、ブラウザのブックマークの
   URL 欄に貼り付けて保存します。両方を別々のブックマークとして登録できます。
   - 自動関連付け版: `src/bookmarklet/comparator.bookmarklet.js`（名前は「請求項グループ比較」など）
   - 手動関連付け版: `src/bookmarklet/relations.bookmarklet.js`（名前は「請求項グループ比較（段落関連 手動）」など）
2. 「書類比較・クレームチェッカー」を開き、**先にページ側の「クレーム解析」を実行**します。
3. 保存したブックマークをクリックすると、画面右下に淡い青のボタンが出ます。

   ```
   請求項グループ比較を開く
   ```

4. そのボタンを押すと、比較専用の新しいタブが開きます。
   （手動関連付け版のボタンは「請求項グループ比較を開く（段落関連 手動）」です）

解析前に実行した場合は、入力欄の `【請求項○】` から読み取るフォールバックが働きます。
どちらからも取得できないときは、エラーで止まらず次の案内を出します。

```
請求項を取得できませんでした。先にクレーム解析を実行してください。
```

## 比較タブの使い方

| 場所 | 操作 |
|---|---|
| ヘッダー | `比較` / `グループ編集` の切り替え。縦スクロールしても残ります |
| 操作バー | グループ選択、自動グルーピング再実行、グルーピング強度（広め/標準/厳密）、列数（自動/2〜6）、表示密度（標準/コンパクト/ゆったり）、強調モード |
| 段落バー | `全体` `段落1` `段落2` … 選択した段落を全カードで強調します |
| カード | 請求項番号・独立項/従属項・引用請求項・カテゴリーと、段落ごとの本文 |

- **段落の同期選択**: どれか1枚のカードの段落をクリックすると、同じグループの他のカードでも
  **対応する段落**が同時に強調されます。段落番号が同じとはかぎりません。
  日本語クレームの書き方に共通する次の性質だけを手掛かりにしています。
  - 「…選択するか、**又は、**」のように接続語で続く段落、「…は、」「…として、」で述語が来ていない段落、
    インデントの深い列挙は、**1つの塊**として一緒に反応します
  - 構成要件の**述語は段落の末尾**に来るので、末尾の一致を独立に重く見ます
    （前半が同じで「蓄積し／生成し／送信し」だけが違う段落を取り違えません）
  - 「◯◯において XX を**送信**すること」と「△△において XX を**受信**すること」は
    主体が入れ替わっただけの同じやり取りなので、**対応させます**
    （この畳み込みは対応付けの計算だけで、表示にもグループ分けにも効かないので、
    送信／受信の違いそのものは今までどおり読めます）
  - 一方で2段落に割れている内容が他方では1段落にまとまっている場合、**どちらを選んでも
    同じ組が反応します**（1対多・相互対応）
  - 十分に対応する段落が無いときは、同じ段落番号へは落とさず `類似段落なし` と控えめに表示します
    （誤った段落を強調するより、何も強調しないことを優先しています）
- **強調モード**: `選択段落を強調`（他を薄く）と `選択段落のみ`（他を隠す）を切り替えられます。
- **本文は原文のまま**です。正規化した文字列は比較にしか使いません。段落番号は比較画面専用の表示です。

### グループ編集

グループ一覧の各行の `編集` から、自動生成済みのグループも含めて後から編集できます。

- グループ名の変更／請求項の追加・削除・並べ替え（`←` `→` `×` とドラッグ＆ドロップ）
- 追加候補の**昇格**（正式メンバーにする）・**除外**
- 選択した請求項を別グループへ**移動**（元から外す）または**複製**（元に残す）
- グループの分割・統合・複製・削除、保存・キャンセル、直前操作の取り消し、自動生成時の状態へ戻す
- 100 請求項をドラッグ＆ドロップだけに頼らないための**一括編集欄**（`1,5,12,20` 形式）
- 複数グループをまとめて読み書きするテキスト形式

  ```
  # 独立方法クレーム
  1,26,32,35

  # 装置クレーム
  15,30,33,39
  ```

  重複・存在しない請求項番号・不正な書式は、**置き換える前に**一覧で示します。

削除・統合・分割・置き換え・自動状態への復帰など影響の大きい操作は、画面内の確認バーで尋ねます
（ページを止めるモーダルは使いません）。自動グルーピングを再実行しても、
手動で作成・編集したグループは**確認なしに上書きしません**。

## 手動関連付け版の使い方

請求項のグループ分け・カード表示・グループ編集は自動版と同じです。違うのは段落の扱いだけ。

1. 各段落の左にチェックボックスが付きます（段落のどこをクリックしても選べます）。
2. 比べたい段落を、**複数の請求項にまたがって・同じ請求項から複数でも**選びます。
3. 選択中は画面下の固定領域に内容が出るので、下へスクロールしても何を選んでいるか分かります。

   ```
   4段落を選択中
   ・請求項1：段落1、2
   ・請求項2：段落4
   ・請求項5：段落4
   ［関連を作成］［選択解除］
   ```

4. 「関連を作成」で **関連** ができます。名前は既定で `関連1` `関連2` …（作成時・作成後どちらでも変更可）。
   短いメモも付けられます。
5. 上部の関連バーで `関連なし / 関連1 / 関連2 …` を切り替えます。関連を選ぶと、
   **登録した段落だけ**が同じ色で強調され、それ以外は薄くなります。
   関連名・登録段落数・対象の請求項番号と段落番号・メモも一覧で確認できます。

### 関連の編集

「関連を編集（段落を選び直す）」を押すと、登録済みの段落がチェック済みで開きます。
そこからチェックを足す／外すして「保存」。名前とメモは関連の詳細欄から直接変更できます。
複製・削除もでき、削除は確認してから実行します。**同じ段落を複数の関連へ登録**できます。
関連は請求項グループごとに分かれて保持されます。

### 書き出し・読み込み

- **JSONで書き出す**: グループ名・請求項番号・関連名・関連に属する請求項番号と段落番号・
  各段落の短い原文・メモを含む JSON をブラウザの標準ダウンロードで保存します
  （外部サーバへは一切送りません）。閲覧用のテキスト出力もありますが、
  **読み戻しの正式形式は JSON** です。
- **読み込む**: ファイルを選ぶか内容を貼り付けて「検証」。形式・バージョン・必須項目に加えて、
  請求項番号と段落番号が現在の文書に存在するかを確認します。確認後に
  `現在の設定を置き換える` / `現在の設定へ追加する` / `キャンセル` を選べます。
- 別の案件へ読み込んだ場合でも、**文字列類似度等による自動対応づけはしません**。
  見つからないものは次のように未解決として示すだけです。

  ```
  請求項12の段落4が見つかりません
  ```

  JSON に入っている段落の原文は、利用者が元の関連を確かめるための参考情報です（自動推定には使いません）。

## 自動グルーピングの考え方

4 つの作り方を併走させ、結果を重ねて出します。1 つの請求項が複数のグループに属してよく、
1 グループは最大 100 請求項です。各グループには「なぜ束ねたか」の根拠が付きます。

| strategy | 何を見るか |
|---|---|
| `tree` | 複数の独立項を起点とするサブツリーの**形の一致**。一致したら、親から見た相対位置（DFS 前順の同じ位置）どうしを対応させる |
| `category` | 独立項を請求項カテゴリー（末尾語から判定）でまとめる |
| `text` | 最も似ているペアを種にして育てるクラスタリング。引用先が違っても字面が近ければ拾う |
| `cite` | 同じ請求項集合を引用する請求項／同じ親を引く兄弟従属項 |

`text` では「A と B が似ている、B と C も似ている」だけで A・B・C をまとめません。
追加は**グループ全体との平均**と**どのメンバーとも最低限似ていること**の両方で判断し、
一部とだけ似ているものは確定せず **追加候補** として別に持ちます（比較タブでは破線のカードで
一緒に並び、グループ編集から正式メンバーへ昇格できます）。どのグループにも入らなかった請求項は
**「未グループの請求項」** としてまとめて出るので、取りこぼしがありません。

グルーピング強度は `広め`（既定）→ `標準` → `厳密` の順に候補が絞られます。
「多少過剰でも拾う」が既定なのは、**送信/受信・同じ/異なる**のような差を機械が先に捨ててしまうと、
まさに見つけたい違いが見えなくなるためです。

類似度の重みとグループ化のしきい値は、すべて `src/core/settings.js` の 1 か所にあります
（調整のために他のファイルを触る必要はありません）。配分は
文字3-gram 40% / 共通単語・共通連続文字列 30% / 段落構造 15% / 共通用語クラス 10% /
引用関係・ツリー位置・カテゴリー・項種別 5%。段落の対応付けは
共通単語 35% / 末尾（述語）25% / 文字3-gram 20% / 共通連続文字列 10% / 段落長 10%
（＋用語クラスの小さな加点）。段落を塊にまとめる接続語と、向きが逆なだけの語（送信/受信など）も
同じ設定ファイルにあり、日本語の書き方の話として 1 か所で編集できます。

詳しい根拠は [docs/design.md](docs/design.md) を参照してください。

## 案件非依存であること

**中心処理には、特定の案件の請求項番号・番号差・技術用語・カテゴリー・グループ構成・
ツリー形状を一切持たせていません。** すべて対象案件から抽出した情報だけで判定します。

| 層 | 役割 | 案件依存 |
|---|---|---|
| `src/extract/extractor.js` | **クレームチェッカーとの接続部分**。`#claim_mark` / `CLMNM<n>` / `#claim_cite` / `zenki_wdXX` / `#doc1` という**ページの**セレクタを知っているのはここだけ | ページ構造には依存（案件には非依存） |
| `src/core/*` | 上の抽出結果を受け取る汎用データ処理。DOM もページも案件も知らない | 非依存 |
| `src/view/*` | 汎用データを描画する。請求項の中身を知らない | 非依存 |

接続部分が返す汎用データはこの形です。以降の処理はこれしか見ません。

```javascript
{
  number,               // 請求項番号（連番でなくてよい・欠番があってよい）
  rawText,              // 原文（表示用番号のみ除去）
  segments,             // [{ index, text, depth }] 段落
  citations,            // 直接引用（引用一覧を優先、無ければ本文解析）
  isIndependent,
  categoryLabel,        // 末尾語そのもの（未知の語でもよい）
  categoryKey,          // カテゴリー系列。表に無い末尾語は末尾語から作る
  termClasses,          // zenki_wdXX（補助情報）
  segmentTermClasses,   // 段落ごとの用語クラス
  normalized,           // 比較用（表示には使わない）
  normalizedSegments,
}
```

正規化は**辞書を持ちません**（定型語の一覧・ストップワード辞書・技術用語辞書を作らない）。
個別に落とすのは日本語クレームの参照表現である「前記」だけで、
「ステップ／手段」のようなカテゴリー差は辞書で畳まず全体の一致率に埋もれさせています。

既知のカテゴリー表（方法・装置・回路・プログラム・媒体・システム…）は判定の**補助**にすぎません。
表に無い末尾語（例: 樹脂組成物、多形結晶）が来ても処理は続き、末尾語ごとに別系列として扱います。
分野・請求項数・ツリー形状が変わっても動くことは `tests/generic.test.js` で検証しています。

```sh
# リポジトリのルートで
node --test "claim_group_comparator/tests/*.test.js"

# または claim_group_comparator/ で
npm test
npm run build:bookmarklets     # 2つの版（comparator*.js と relations*.js）を再生成
```

- `src/core/` `src/extract/` `src/view/` `src/bookmarklet/common/` が**手編集する正本**です。
- `src/bookmarklet/comparator*.js`（自動版）と `relations*.js`（手動版）は**生成物**
  （先頭に DO NOT EDIT バナー）。
  ソースを直したら `npm run build:bookmarklets` を実行してください。`tests/build.test.js` が
  生成物とソースの同期を検査するので、忘れるとテストが落ちます。
- テストは共有の `fixtures/claim-checker/` を読みます。fixtures が無い環境では該当テストが skip されます。
- 1 行化は最小 URL エンコード（`%` → `%25`、`#` → `%23`、改行 → `%0A`）で、コメントも改行も残します。
- 2 つの版は `scripts/build-bookmarklets.js` の `TARGETS` で定義します。共有するのは
  コア（設定・引用解析・正規化・段落分割・ツリー・類似度・請求項グルーピング・状態・レイアウト）と
  画面の基本部品（`dom` / `styles` / `editor`）。**手動版の束には `segmatch.js` を入れません**
  （手動版が段落の類似度計算を内部で実行しないことを、`tests/build.test.js` が検査します）。

### 実装上の約束

- **eval・`document.write`・script 要素の注入を使わない。** 対象ページの CSP は `script-src 'self'` で、
  `window.open` で開いた `about:blank` はこれを継承します。比較タブの中身は親タブの JS から
  DOM API だけで組み立てます。
- **`innerHTML` を使わない。** 本文は必ず `textContent` で入れます（HTML エスケープ漏れが構造的に起きない）。
- 元ページに足すのは `#jcgc-launcher` と `#jcgc-launcher-style` の 2 つだけ。`Checker` オブジェクトにも
  既存 DOM にも触れません。クラス・ID はすべて `jcgc-` 接頭辞です。
- 外部ライブラリ・外部サーバ・`localStorage` を使いません（状態は比較タブを閉じるまで。
  `toJSON()` / `loadJSON()` があるので後から保存を足せます）。

## 制約

- **元のクレームチェッカーのタブを閉じると、比較タブの操作ができなくなります**（表示中の内容は
  そのまま読めます）。比較タブの JS は親タブのクロージャで動いているためで、CSP の制約上
  比較タブ側にコードを置くことはできません。元タブを閉じるときに比較タブへ案内を出します。
- 状態はタブを閉じるまでの保持です（永続化なし）。
- グルーピングは字面と構造による**候補作成**であり、法的な同一性の判断ではありません。
