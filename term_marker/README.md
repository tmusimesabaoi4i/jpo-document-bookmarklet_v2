# term_marker — 「前記XXXX」語句カラーマーキング

J-PlatPat / JPO 由来の特許文書 HTML（`<pre>` ベースの請求の範囲・明細書・手続補正書など）の上で実行し、
「前記固定ルート」「前記第１の他の通信装置」のような **「前記XXXX」の XXXX を自動抽出して、語句ごとに異なる色で
マーキングする**ブックマークレットです。右上の操作パネルで対応表（語句 ↔ 色）を直して「実行」すれば、
その場でマーキングを作り直せます。
軽量版プロファイル（ブックマークレットのみ・ローカル UI なし）のプロジェクトです。ビルド（1 行化）とテストだけ持ちます。

- 完全にブラウザ内で動作し、ページ内容を外部へ送信しません。外部ライブラリ・CDN に依存しません。
- 本文 HTML を `innerHTML` で書き換えることはせず、テキストノードだけを `<span data-jpo-marker>` で包みます。
  `<u>`（補正箇所）など既存のタグはそのまま残ります。

## クイックスタート（ブックマーク登録）

1. `src/bookmarklet/marker.bookmarklet.js` を開く
2. ファイル全体（`javascript:` から始まる 1 行）をコピー
3. ブラウザの新規ブックマーク URL 欄に貼り付け（名前は「Marker」など）
4. JPO の文書 HTML（またはダウンロードした HTML）を開いた状態でブックマークをクリック

クリックした時点で「自動抽出 → 色割当て → マーキング」まで終わり、右上にパネルが出ます。

## 使い方

### パネル（右上・非モーダル）

```
┌──────────────────────────────────────────┐
│ Marker v1.0.0          20語 / 113箇所  －  × │  ← ヘッダをドラッグで移動
├──────────────────────────────────────────┤
│ [表] [自動抽出] [印刷] [出力] [実行]          │
│ [＋追加] [文字数↓] [色を再割当て] [全解除] [初期化して再抽出] │
│ 一致: [全文一致 ▾]  ☑ 下線                   │
├──────────────────────────────────────────┤
│ ⋮⋮ ☑ ■ [ルーティングテーブル ]  3件      ↑ ↓ × │
│ ⋮⋮ ☑ ■ [第１の他の通信装置   ]  2件      ↑ ↓ × │
│ ⋮⋮ ☑ ■ [他の通信データ       ]  5件 包含 ↑ ↓ × │
│ …                                          │
├──────────────────────────────────────────┤
│ 20 語を自動抽出し、113 箇所をマーキングしました │
└──────────────────────────────────────────┘
```

| 操作 | 動作 |
|---|---|
| **閉じる ×** | パネルを閉じる（マーキングは残る）。右上に小さな「Marker」ボタンが残り、クリックで再表示 |
| **－** | ヘッダだけに最小化 |
| **表** | 対応表の表示／非表示 |
| **自動抽出** | ページを再解析し、**未登録の候補だけ末尾に追加**（手で直した行は消えない） |
| **印刷** | `window.print()`。パネルは印刷されない。マーキング色は `print-color-adjust: exact` で印刷に反映 |
| **出力** | マーキング済み HTML を `元ファイル名_marked.html` としてダウンロード（後述） |
| **実行** | 現在の表の内容でマーキングを全部作り直す（編集の「確定」） |
| **＋追加** | 空行を追加（自動抽出できなかった語句を手で登録） |
| **文字数↓** | 長い語句 → 短い語句の順に並べ替え（包含問題の回避） |
| **色を再割当て** | 上から順に 25 色パレットを配り直す |
| **全解除** | マーキングだけ解除（表は残る） |
| **初期化して再抽出** | 表を捨てて抽出し直す（誤操作防止のため 2 回押し） |
| 各行 ☑ | 有効／無効（無効行はマーキングしないが出現数は表示） |
| 各行 ■ | クリックでカラーピッカー。色の変更は即座に反映 |
| 各行 語句欄 | 直接編集（Enter で実行）。入力中は「n件\*」で仮の出現数を表示 |
| 各行 件数 | 実際にマーキングした数。0 件は薄い警告色。上位の語句と重なって減った場合はツールチップに内訳 |
| 各行 ⋮⋮ / ↑ ↓ | ドラッグまたはボタンで並べ替え。**表の順序＝優先順位** |
| 各行 × | 削除（「実行」で反映） |

### 典型的な流れ

1. ブックマークをクリック → 自動抽出とマーキングが終わっている
2. 表を眺めて、誤抽出（例: `宛先` と出たら `宛先アドレス` に）を 1〜2 箇所直す／不要な行を × で消す／足りない語句を「＋追加」
3. 「実行」

### 一致方法

- **全文一致（初期値）**: 登録した語句の出現箇所をすべてマーキング（「前記」が付いていない初出も追跡できる）
- **「前記」付きのみ**: 直前が「前記」の箇所だけマーキング（「前記」自体は色付けしない）

### 包含関係と優先順位

`第１通信装置` と `通信装置` を両方登録した場合、**表の上にある語句が優先**され、
すでに確定した範囲と重なる候補は捨てられます。短い語句が上にあると長い語句が隠れるので、
その行には「⚠包含」が表示されます。「文字数↓」を押せば長い語句が上位になり解決します
（正しい順のときは参考表示の「包含」になります）。同じ語句が 2 行あれば下は「重複」として無視されます。

### 出力 HTML

- 元本文・元の装飾（`<u>` など）・現在のマーキング・語句と色の対応表を含む単独の HTML（UTF-8）
- 冒頭に印刷可能な静的な対応表（語句を自身の色で表示＋件数）を置き、操作パネルは含めない
- 対応表の設定は `<script type="application/json" data-jpo-marker-state>` として埋め込まれるので、
  **出力 HTML の上でもう一度ブックマークレットを実行すると、同じ表を読み込んで編集を続けられる**
- ファイル名: `元ファイル名_marked.html`（パスから取れない場合は `jpo_marked_YYYYMMDD_HHMMSS.html`）
- `Blob` + `URL.createObjectURL` によるクライアント側ダウンロード。サーバ通信はしない

## 主要設計（詳細は [docs/design.md](docs/design.md)）

- **論理テキスト＋位置マップ**: `document.body` 配下のテキストノードを集め、`\r` `\n` を除いた連結文字列を作る。
  各論理文字に (テキストノード index, ノード内オフセット) を持たせるので、改行や `<u>` の境界をまたぐ語句も
  1 回の `indexOf` で見つかり、元 DOM 上の位置に戻せる。
- **自動抽出**（`scanTerm` / `extractTerms`）: 「前記」の直後から、文字種（漢字・カタカナ・英数字）で名詞句を読み、
  助詞・句読点・接続表現（及び／又は／に対して…）で止める。「の」は左が修飾語（第N／他／複数…）のときだけ連結、
  接尾語（内／宛／以上…）は直後が境界のとき語句から外す。純関数なので改善はこの節だけで完結する。
- **重複排除**: 表の順に一致範囲を確定し、`Uint8Array` の占有マスクで重なる候補を捨てる。
- **DOM 適用**: 範囲をテキストノードごとの区間に分解し、ノード単位で 1 回だけ分割・置換（`DocumentFragment`）。
- **解除**: `[data-jpo-marker]` の span だけを外して `normalize()`。ページ由来の span とは属性で区別。
- **UI**: Shadow DOM 上のパネル（ページ CSS と相互に干渉しない）。`window.__jpoTermMarker` の 1 名前空間だけを使う。

## 開発（ビルドあり・依存ゼロ）

- 正本は `src/bookmarklet/marker.js`。編集したら `node term_marker/scripts/build-bookmarklet.js` で
  `marker.bookmarklet.js` を再生成する（最小 URL エンコード: `%`→`%25`、`#`→`%23`、改行→`%0A`。コメントも改行も
  そのまま保持されるのでロジックがずれない）。
- `node --test "term_marker/tests/*.test.js"` で、生成物の同期・fixture に対する挙動・パレット品質を検証する。
- 実行時コードは `eval` / `new Function` / `innerHTML` 代入 / 通信 API を含まない（テストで禁止）。
- 抽出の起点語を増やす場合は `PREFIXES`（既定 `['前記']`）、除外文字は `IGNORE_CHARS`、パレットは `PALETTE`。

## 既知の制約

- 自動抽出はヒューリスティックなので、「AのB」を 1 語にすべきか（例: 前記車両の走行状態）や送り仮名を含む語
  （例: 組み合わせ）は取りこぼす／切り過ぎることがある。表で直すことを前提にしている。
- 一致は完全一致（全角／半角や表記ゆれは同一視しない）。
- 26 語目からはパレットの色を循環して使う（パネルに注記が出る）。
- 印刷の背景色はブラウザ側で「背景のグラフィック」が無効だと出ない。
- `<u>` の下線と本ツールの下線（2px）は近い位置に並ぶ。気になる場合は「下線」チェックを外す。
- Shadow DOM を使うため、`attachShadow` の無い古いブラウザでは通常 DOM にフォールバックする（ページ CSS の影響を受けうる）。
