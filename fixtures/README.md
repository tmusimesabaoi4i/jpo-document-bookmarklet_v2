# fixtures — 対象JPOページのスナップショット台帳

このフォルダは、各プロジェクトが対象とする特許庁（JPO）ページの保存済み HTML スナップショットを集約した**共有資産**です。ブックマークレットの開発・動作確認・テストの土台として、複数プロジェクトから参照されます。

- 構成規約: `fixtures/<ページ種別>/<世代>/<ページ名>.html`
- 世代: `new` = 新版ページ（`www.beta.jpo.go.jp` 系）／ `legacy` = 旧版ページ（`gem.prototype.jpo.go.jp` 系）
- ここに置くのは「対象ページの実物スナップショット」だけです。ロジックの期待値（ゴールデンケース）は各プロジェクトの `examples/` に置き、混同しないこと。

#### 引用パターン上限到達スナップショットについて

`new/書類比較・クレームチェッカー_引用パターン上限到達.html` は、ページ側が

> ★全請求項間引用パターン全展開上限数(5000)到達のため、上限数の引用パターンについて解析します。★

を表示している状態のスナップショットです。この状態では **`#claim_tree` の罫線ツリーが先頭 5000 パターン分しか描画されず、残りが丸ごと欠落します**（実測: 全 92 請求項・857 エッジのうち 22 請求項・100 エッジのみ）。罫線としては正しいため構文エラーにならず、**黙って誤った解析結果になる**のが厄介な点です。

一方 `#claim_cite`（引用一覧）は上限到達時でも全 92 請求項を列挙し、その「引用請求項」欄（＝直接引用元）から完全な引用関係を復元できます。ただし同じ引用一覧でも「**被引用請求項**」欄は打ち切り後の不完全な値（857 中 219 エッジ分のみ）なので、引用関係の復元に使ってはいけません。

このスナップショットは、その両方の性質を固定するための回帰テスト用資産です。

## 既知の注意点

- 各 HTML の冒頭には、ブラウザ保存時のコンパニオンフォルダ（`./…_files/`）への参照が残っていますが、そのフォルダは**意図的に保存していません**。ブラウザで開くとスタイルなしで表示されますが、DOM 構造の確認・テストには影響しません。壊れているわけではないので「修復」は不要です。
- スナップショットを追加・更新したときは、この台帳と、参照元プロジェクトのテスト・README を併せて更新してください。
- 取得日はファイルの git 履歴を参照してください。
