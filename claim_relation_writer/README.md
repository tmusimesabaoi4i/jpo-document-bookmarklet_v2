# Claim Relation Writer

特許実務者向けのローカルツールです。クレームの引用関係（クレームツリー）と、指摘する請求項・関連する請求項を入力すると、そこから影響を受ける請求項の範囲（引用関係をたどって波及する範囲）を自動的に再帰計算し、明確性・サポート要件の拒絶理由の定型文を生成します。

- 入力: 罫線文字で書いたクレームの引用関係 ＋ 指摘する請求項・関連する請求項
- 処理: 引用関係をグラフとして解析し、指摘・関連の各請求項から「引用してくる請求項」を漏れなくたどって影響範囲を計算
- 出力: 明確性またはサポート要件の指摘文（定型文）
- 完全にブラウザ内で完結し、外部にデータを送信しません

## クイックスタート

インストールもサーバーの起動も不要です。`src/local/index.html` をブラウザでダブルクリックして開くだけで使い始められます。

## 使い方（4ステップ）

画面上部のステップ表示（「1 クレーム構造」〜「4 文章生成」）をクリックすると、そのステップの画面に遷移します（1ステップ＝1画面）。Step 2 以降へ移るときはクレーム構造が自動で解析され、構文に誤りがあれば行番号付きのエラーが表示されて Step 1 に留まります。

1. **クレーム構造を入力**: 罫線文字（┳ ┣ ┃ ┗ ━）で書いたクレームツリーをテキストエリアに貼り付けます。「サンプル（木構造1）を読み込む」ボタンで試すこともできます。
2. **指摘する事項を選択**: 「明確性」または「サポート要件」をラジオボタンで選びます。
3. **請求項を指定**: 「指摘する請求項」（必須）と「関連する請求項」（同様の指摘が及ぶ請求項・空欄可）を、読点・カンマ・空白区切りで入力します。「14-20」のような範囲指定もできます。
4. **生成・コピー**: 結果表示の下にある「生成する」を押すと定型文が表示され、「コピー」でクリップボードにコピーできます（コピーAPIが使えない環境ではテキスト選択方式に自動的に切り替わります）。「最初からやり直す（保存を消去）」ボタンはこのステップの上側にあります。Step 4 を表示中は、キーボードショートカット Ctrl+Enter（生成する）／Alt+Enter（コピーボタンが有効なときにコピーする）も使えます。

### 実例（`examples/examples.js` の `case1-clarity`）

サンプルの木構造1（30項のクレームツリー）に対して、指摘する請求項＝1、関連する請求項＝21、指摘事項＝明確性 を指定した例です。

    ┣  8
    ┣  9 ┳ 10

    ┣ 12
    ┗ 13 ┳ 14

　        ┣ 16

　        ┣ 18
　        ┣ 19
　        ┗ 20
 21 ┳ 22

指摘する請求項: `1` ／ 関連する請求項: `21` ／ 指摘事項: 明確性

生成される文章:

```
　請求項２１にも同様の点が指摘される。

　よって、請求項１-２６に係る発明は明確でない。
```

## 入力記法

クレームツリーは罫線文字で表現します。列位置（インデントの幅）ではなく罫線文字そのものを見て解析するため、半角スペース・全角スペース・タブが混在していても正しく解析できます。

| 文字 | 意味 |
| --- | --- |
| `┳` | ここで分岐が始まる（直前の請求項が親になる） |
| `┣` | 分岐の子（その分岐でまだ兄弟が続く） |
| `┗` | 分岐の子（その分岐の最後。分岐を閉じる） |
| `┃` | 上位の分岐がまだ続いていることを示す縦線（行頭に置く） |
| `━` | 分岐を作らず、そのまま次の請求項へ連結する |

例えば `1 ┳ 2 ━ 3` は「2が1を引用し、3が2を引用する」という意味になります。

同じ請求項番号がツリー中に複数回現れた場合は、常に同一の請求項として扱われます。これにより、複数の親請求項を引用する多項従属請求項（例: サンプルの木構造2・木構造5にある請求項12）も正しく表現できます。同一番号が行頭に再掲されても、新しい独立請求項としては扱われません。

細線の罫線文字 `┬ ├ │ └ ─ ｜` も、それぞれ `┳ ┣ ┃ ┗ ━ ┃` と同じ意味で解釈されます。対応表にない罫線記号（`═` `║` など）は解釈できないためエラーになります。

より詳しい文法・正規化ルール・解析アルゴリズムは [`docs/specification.md`](docs/specification.md) を参照してください。

## 状態の自動保存

入力内容はブラウザの localStorage に自動保存され、タブやブラウザを閉じて再度開いても続きから再開できます。localStorage が使えない環境（一部のプライベートモードなど）では、保存できない旨を画面に表示したうえでメモリ上の状態のみで動作を続けます。保存内容をすべて消してやり直したい場合は、Step 4 の「最初からやり直す（保存を消去）」ボタンを使ってください。

なお、生成済みの文章は「生成したときの入力」と結び付けて管理されます。クレーム構造・指摘事項・請求項の指定を変更すると古い生成文とコピーボタンは自動的に無効化され、復元時も入力と食い違う古い生成文は表示されません（誤った請求項番号の文章を誤ってコピーしないための安全設計です）。

## 対象ページと動作確認（ブックマークレット版）

「書類比較・クレームチェッカー」（特許庁の新版 www.beta.jpo.go.jp ／旧版 gem.prototype.jpo.go.jp）向けのブックマークレット版を実装済みです。ページ上でブックマークレットを起動するとモーダルウィンドウが立ち上がり、ページのクレーム構造（`#claim_tree .div_tree`）を自動収集したうえで、モーダル内で指摘事項の選択・請求項の指定・生成・コピーまでを完結できます。コアロジック（`src/core/`）はDOM非依存のUMDモジュールとして書かれているため、ローカル版と同じ計算・同じ文章がそのまま得られます。導入手順・使い方・設計根拠は [`src/bookmarklet/README.md`](src/bookmarklet/README.md) を参照してください。

動作確認用に保存した対象ページのスナップショットは、リポジトリ共有の [`fixtures/claim-checker/`](../fixtures/claim-checker/)（`new/`・`legacy/`）にあります。

## 開発（テスト・ビルド）

依存パッケージはありません。Node.js 18 以降で動作します（開発時は v24.14.1 で動作確認済みです）。

```
npm test
```

または

```
node --test
```

で `tests/` 以下のテストスイートが実行されます。ブラウザ上で直接動作を確認したい場合は `tests/browser-test.html` を開いてください。

なお、`bookmarklet.test.js` の実ページ抽出テストは、リポジトリ共有の `../fixtures/claim-checker/` を読み込みます。このプロジェクトのフォルダ単独をコピーした環境ではこのテストだけ失敗するため、テストはリポジトリ全体をチェックアウトした状態で実行してください。

ブックマークレット版の生成物(`src/bookmarklet/{new,legacy}/collector.js`・`collector.bookmarklet.js`)を再生成する場合は、次のコマンドを実行します(詳しくは [`src/bookmarklet/README.md`](src/bookmarklet/README.md) を参照してください)。

```
npm run build:bookmarklets
```

## プライバシー

このツールの処理はすべてブラウザ内（クライアントサイド）で完結します。入力したクレーム構造や生成した文章が外部サーバーに送信されることはありません。CDNの読み込みやアクセス解析も一切行っていません。

## 注意事項（OneDrive環境）

このプロジェクトを OneDrive 配下に置いている場合、「ファイルオンデマンド」の設定によってはファイルがクラウド上にのみ存在する状態（オンラインのみ）になっていることがあります。その状態でオフライン環境で初めて `index.html` を開こうとすると、ファイル本体が端末にまだダウンロードされておらず開けないことがあります。一度オンライン環境で開いておく（＝ローカルにダウンロードしておく）か、フォルダを「常にこのデバイス上に保持する」に設定しておくことをおすすめします。
