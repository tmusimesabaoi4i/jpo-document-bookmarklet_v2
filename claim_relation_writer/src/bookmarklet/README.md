# ブックマークレット版

Claim Relation Writer のブックマークレット版は**実装済み**です。対象のWebページ上でブックマークレットを起動すると、モーダルウィンドウが立ち上がってページからクレーム構造を自動収集し、モーダル内だけで指摘事項の選択から文章生成・コピーまでを完結できます。

## 対象ページ

対象は特許庁系ツール「書類比較・クレームチェッカー」です。新版・旧版でDOM構造は同一で、ブックマークレット側が持つ違いはモーダルのタイトルに表示するラベル文言だけです（抽出ロジックの分岐は不要）。

| 版 | ドメイン（パス） | 使用するファイル |
| --- | --- | --- |
| 新版 | `www.beta.jpo.go.jp`（`/main/core/checker/`） | `src/bookmarklet/new/collector.bookmarklet.js` |
| 旧版 | `gem.prototype.jpo.go.jp`（`/core/docs/checker/`） | `src/bookmarklet/legacy/collector.bookmarklet.js` |

動作確認用に保存した両ページのスナップショットはリポジトリ共有の [`fixtures/claim-checker/`](../../../fixtures/claim-checker/)（`new/`・`legacy/`）にあり、219行の機械比較で差異は保存元URL・保存フォルダ名・保存時のインラインpx値のみであることを確認済みです。

## 仕組み

1. ブックマークレットを起動すると、ページ右上にモーダルウィンドウが立ち上がります。ページ側のBootstrap等のCSSと衝突しないよう、`#crw-modal` 名前空間でスタイルを隔離しています。
2. 起動と同時に、ページの `#claim_tree .div_tree`（常駐・非表示のデータ保持用要素。「木構造」ダイアログを開かなくても存在します）からクレーム構造を自動収集します。見つからない場合は `#claim_dialog .div_tree`（「木構造」ダイアログ表示中のみ存在）、さらに任意の `.div_tree` の順に探します。
3. 収集したHTML（`<br>` 区切りのテキスト）を改行に変換してプレーンテキスト化し、ローカル版と同じ `parseClaimTree` にそのまま渡します。
4. モーダルはウィザード形式ではなく1画面フォームで、ローカル版の Step 2〜4（指摘事項の選択・請求項の指定・生成・コピー）に相当する操作をこの1画面だけで完結できます。書類（doc1/doc2）を選ぶUIはありません。ページ側のDOMにその区別を持つ要素が存在しないためです。
5. コアロジック5モジュール（parser・formatter・resolver・generator・session）はローカル版と全く同じファイルをそのまま同梱しているため、同じ入力からは同じ計算結果・同じ生成文が得られます。

## 導入手順

1. 対象の版に応じて、次のファイルをテキストエディタで開きます。
   - 新版（`www.beta.jpo.go.jp`）: `src/bookmarklet/new/collector.bookmarklet.js`
   - 旧版（`gem.prototype.jpo.go.jp`）: `src/bookmarklet/legacy/collector.bookmarklet.js`
2. ファイルの中身（`javascript:` から始まる1行全部）をコピーします。
3. ブラウザで新しいブックマークを作成し、URL（アドレス）欄に貼り付けます。名前は任意です（例:「CRW収集（新版）」）。
   - ブラウザによっては、`javascript:` から始まるURLをアドレスバーへ直接貼り付けると先頭部分が自動的に無効化されることがあります。その場合はブックマークの編集画面（名前とURLを個別に入力できる画面）のURL欄に貼り付けてください。
4. 対象ページでクレーム解析を行った状態でブックマークをクリックすると、モーダルが起動します。

## 使い方

- **起動時に自動収集**: モーダルを開くと同時にページから木構造を取得し、解析結果のサマリ（請求項数・独立請求項）を表示します。
- **収集失敗時は手貼り可**: ページからクレーム構造が見つからない場合はエラーメッセージが表示され、「収集した木構造（編集できます）」を開くと木構造を手動で貼り付けられます。
- **ページから再取得**: 同欄の「ページから再取得」ボタンで、ページから木構造を取得し直せます。編集中の内容が破棄される場合は確認ダイアログが出ます。
- **陳腐化警告**: モーダルを開いた後にページ側で「クレーム解析」が再実行されると（`MutationObserver` で `#claim_tree` の変化を検知）、警告が表示されて生成ボタンが一時的に無効化されます。「ページから再取得」、または木構造欄を手動編集することで解除されます。
- **上流変更で自動無効化**: 木構造・指摘事項の種別・指摘/関連する請求項のいずれかを変更すると、生成済みの文章とコピーボタンは自動的に無効化されます（ローカル版と同じ安全規則）。
- **閉じる**: ヘッダの×ボタン、または Esc キーで閉じます。
- **状態はモーダル内のみ**: モーダルの状態はページの `localStorage` を使わず、モーダルを閉じると失われます（ページのオリジンを汚しません）。
- **コピー**: クリップボードAPI（`navigator.clipboard`）が使えない、または拒否される環境では、テキスト選択方式（`execCommand('copy')`）に自動的にフォールバックします。

## 再生成手順（開発者向け）

ブックマークレット本体を修正する場合は、次のソースファイルを編集してください。

- モーダルUI: `src/bookmarklet/common/collector-app.js`
- コアロジック（ローカル版と共用）: `src/core/parser.js`・`formatter.js`・`resolver.js`・`generator.js`・`session.js`

編集後、次のコマンドで生成物4ファイル（`src/bookmarklet/new/` と `src/bookmarklet/legacy/` それぞれの `collector.js`・`collector.bookmarklet.js`）を再生成します。

```
npm run build:bookmarklets
```

**生成物を直接編集しないでください。** 各生成物の先頭には次の自動生成バナーがあります。

```
/*
 * このファイルは自動生成です — 直接編集しないでください (DO NOT EDIT)。
 * 生成元: src/core/*.js + src/bookmarklet/common/collector-app.js
 * 再生成: npm run build:bookmarklets
 */
```

`tests/bookmarklet.test.js` の「生成物の鮮度」テストが、ビルド結果とコミット済みファイルの一致を検証しています。ソースだけを変更してビルドを忘れると、このテストが「npm run build:bookmarklets で再生成してください」という案内付きで失敗します。

## 技術的な設計根拠

### なぜ自己完結インラインの `javascript:` URLなのか

対象ページには次のContent-Security-Policyが設定されています（保存ページの `<head>` 内、6行目）。

```
Content-Security-Policy: script-src 'self'; script-src-attr 'unsafe-inline'
```

`script-src 'self'` の下では、外部ドメインからスクリプトを読み込むローダ方式も、実行時のコード評価（`eval`・`new Function`・`document.write`・`<script>` 要素の動的挿入など）も使えません。一方、ブックマークレット（ユーザー操作起点の `javascript:` URL）は多くのブラウザでこの制約の対象外として実行されるため、**コア5モジュール＋モーダルUIを1つの `javascript:` URLに自己完結させる方式が唯一現実的な配布方法**です。この前提のもと、`collector-app.js` は実行時コード評価・`document.write`・`<script>` 挿入を一切使わず、DOM APIとクロージャ内の関数だけで動作するように書かれています。`tests/bookmarklet.test.js` の「CSP衛生」テストが、生成物の文字列に `eval(`・`new Function(`・`document.write`・`<script` のいずれも含まれないことを検証しています。

### 1行化の方式（最小URLエンコード）

`scripts/build-bookmarklets.js` は、コメントの除去や改行の削除では**なく**、次の順序の最小URLエンコードで1行化します。

1. `%` → `%25`
2. `#` → `%23`
3. 改行 → `%0A`

`javascript:` URL中に生の `#` が含まれると（`#claim_tree` のようなセレクタ文字列には必ず出現します）、URLのフラグメント区切りと解釈されて、そこから先のコードが失われてしまいます。かといって改行を削除すると、行コメント（`//`）・ASI（自動セミコロン挿入）・正規表現リテラルなどが意図せず壊れる可能性があります。上記の方式であれば、ブラウザが `javascript:` URLを実行する際に自動的にパーセントデコードするため、改行・コメント・コードの意味はすべて実行時に復元され、コア5モジュールのソースを一切変更せずにそのまま連結できます。

## 注意事項

- **URL長**: 1行版は約46KBです（新版: 46,631バイト／旧版: 46,634バイト）。通常のブラウザのブックマークとしては問題ない長さですが、一部のブックマーク同期サービスでは長さ制限に引っかかる可能性があります。
- **実環境での初回確認**: 自動検証は保存済みページのコピーに対して行っているため、実際のライブページでは初回に次のような最小スニペットで動作確認することをおすすめします（`#` を `%23` に置き換えてあります。生の `#` のままだとURLのフラグメントとして切り取られ動作しません）。

  ```
  javascript:alert(document.querySelector('%23claim_tree .div_tree')!==null)
  ```

  対象ページでクレーム解析を行った状態でこれをブックマークとして保存してクリックし、`true` が表示されれば `#claim_tree .div_tree` が見つかっている状態です。`javascript:` URLの実行自体がブロックされる、あるいはクリップボードやCSSの挙動を確認したい場合も、まずこの最小スニペットで切り分けてください。

技術的な詳細（成果物構成・連結順・外殻IIFEの構造・抽出仕様・安全規則・CSS隔離など）は [`docs/specification.md`](../../docs/specification.md) の「11.3 ブックマークレット版」も参照してください。
