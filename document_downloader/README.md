# document_downloader

JPO の文書一覧（経過情報）ページから、**国内書類**（テキスト / 元HTML / 画像 / PDF / 印刷）と
**OPD 書類**（他庁公開情報の一括ダウンロード）をまとめて取得するブックマークレット。
軽量版プロファイル（ブックマークレットのみ・ローカルUIなし）のプロジェクトです。

現行版は **v4**。2026 年の新 JPO 文書一覧ページ（`#lappnum` のリンク文言変更・ダミー行の追加・他庁公開情報欄の追加）に対応しています。

│   │   └── collector.bookmarklet.js   … ブックマーク登録用の 1 行版（scripts/ で生成）
│   └── sort_jpo_downloads.bat         … ダウンロードフォルダを出願番号ごとに仕分ける BAT
├── scripts/
│   └── build-bookmarklet.js           … collector.js → collector.bookmarklet.js（依存ゼロ）
├── tests/
│   ├── collector.test.js              … fixtures に対する収集ロジック・命名規則の検証
│   ├── pdf-and-ui.test.js             … 自前 PDF ライタと UI 配線の検証
│   ├── build.test.js                  … 1 行版の鮮度・不変条件の検証
│   ├── sort-bat.test.js               … sort_jpo_downloads.bat の仕分け動作の検証

対象ページのスナップショットは、リポジトリ共有の [`fixtures/document-list/`](../fixtures/document-list/) にあります。

### 命名ルール

- フォルダ名でプロジェクトを表す（ファイル名には `jpo-document-` などのプレフィックスを付けない）
- `*.js` … 編集用の読みやすいソース
- `*.bookmarklet.js` … ブックマーク URL に貼る 1 行版（`*.js` と同じフォルダにペアで置く）

## クイックスタート（ブックマーク登録）

1. `src/bookmarklet/collector.bookmarklet.js` を開く
2. ファイル全体（`javascript:` から始まる 1 行）をコピー
3. ブラウザの新規ブックマーク URL 欄に貼り付け
4. JPO にログインした状態で対象ページを開き、ブックマークをクリック

旧版を使う場合: `archive/v3-collector/`（v3）／`archive/v2-collector/`（v2）／`archive/v1-single/`（v1）

## 対象ページ

| 世代 | URL 形式 | 対応 |
|---|---|---|
| 新版（現行） | `https://www.beta.jpo.go.jp/main/core/jsv/doclist/exam/{11桁の出願番号}/` | ✅ 国内書類 + OPD |
| 新版（2024 年ごろのUI） | 同上 | ✅ 国内書類（OPD 欄なし） |
| 旧版 | `http://gem.prototype.jpo.go.jp/core/docs/jsv/doclist/exam/{11桁の出願番号}/` | ✅ 国内書類（OPD 欄なし） |

`{11桁の出願番号}` は `1`（特許）/`2`（実用新案）/`3`（意匠）/`4`（商標）+ 西暦4桁 + 連番6桁。
例: `12023170613` → `特願2023-170613`。

**JPO の認証セッションが必要です。** 書類実体も OPD 生成 API も、ログイン済みの同一オリジン
リクエストとしてのみ動作します。認証を回避する処理は入っていません（401/403 は「認証切れまたは
権限不足」として表示されます）。

## 国内書類と OPD 書類の違い

| | 国内書類 | OPD 書類（他庁公開情報） |
|---|---|---|
| 取得元 | `#doclist` の `tr[data-content-id]` | `div.tbl_others` の `input[name="pubnum"]` |
| 単位 | 1 書類（例: 請求の範囲・明細書・図面） | 1 公開番号（例: `EP4312460A1`） |
| 取得方法 | 書類実体参照 API を直接 GET し、こちらで整形して保存 | JPO の一括生成 API に依頼 → 生成完了を待って JPO が作った書庫を保存 |
| 出力 | `.txt` / `.html` / `.png` / `.pdf` / 印刷 | JPO が返すファイル（`individual`＝複数ファイル / `consolidated`＝単一ファイル） |
| ファイル名 | `出願番号_YYYYMMDD_文書名.拡張子` | `出願番号_元のZIPファイル名`（元名は `Content-Disposition` 優先） |
| 所要時間 | 即時 | 非同期生成のため待ちが発生（既定で最大 180 秒） |

モーダル右側は上が「国内書類」、その下に区切り線と見出しを挟んで「OPD書類（他庁公開情報）」。
**全選択／全解除は国内書類用と OPD 用で完全に分かれています**（片方の操作でもう片方の選択は変わりません）。

## 出力形式（国内書類）

| 形式 | 拡張子 | 内容 |
|---|---|---|
| テキスト | `.txt` | 書類実体 HTML をブロック単位で改行したプレーンテキスト（`script`/`style` は除去） |
| 元HTML | `.html` | 書類実体 API が返した HTML をそのまま保存 |
| 画像 | `.png` | 書類実体内のページ画像を PNG に変換して 1 ページ 1 ファイル |
| PDF | `.pdf` | **ページ画像を A4 に収めて結合した画像 PDF**（外部ライブラリ不使用） |
| 印刷 | — | 別ウィンドウに書類を書き出して印刷ダイアログを開く（「PDFとして保存」も可） |

- PDF は `CompressionStream` が使えて 4 メガピクセル以下なら**可逆（FlateDecode）**、それ以外は
  JPEG（DCTDecode, 品質 0.92）で埋め込みます。
- **画像を持たない文書は PDF 化できません**（その旨をログに出してスキップします）。
  テキスト主体の書類を PDF にしたい場合は「印刷画面を開く」→「PDFとして保存」を使ってください。
  表示名だけ変えた見せかけの PDF 機能ではなく、印刷とは別物として実装しています。

## ファイル名

**正式な命名規則は次のとおりです。国内書類と OPD で規則が違います。**

### 国内書類

```
出願番号_YYYYMMDD_文書名.拡張子
```

例:

```
特願2022-122252_20260602_手続補正書（自発・内容）.pdf
特願2022-122252_20260602_手続補正書（自発・内容）.html
特願2022-122252_20260602_手続補正書（自発・内容）.txt
特願2022-122252_20220729_図面_p001.png     ← 画像が複数ページのとき
特願2022-122252_20220729_図面_p002.png
特願2022-122252_20220729_図面_p004.png
```

- 画像が 1 ページだけのときはページ番号を付けません（`…_図面.png`）。複数ページのときだけ
  末尾に `_p001` / `_p002` … が付きます。
- ログ保存も同じ並びで `出願番号_YYYYMMDD_log.txt` になります。

### OPD 書類（他庁公開情報）

```
出願番号_元のZIPファイル名
```

例（JPO が返した元ファイル名が `EP4312460A1.zip`、対象が `特願2022-122252` の場合）:

```
特願2022-122252_EP4312460A1.zip
特願2022-122252_US20240040620A1.zip
特願2022-122252_WO2024012345A1.zip
```

- **OPD には日付を付けません。**`出願番号_YYYYMMDD_OPD…` にはなりません。
- 元ファイル名は `Content-Disposition`（`filename*` / `filename` の両方に対応）から取り、
  パス成分があれば basename だけにし、Windows で使えない文字を置換してから
  先頭に `出願番号_` を付けます。すでに `出願番号_` で始まっている場合は二重付与しません。
- `Content-Disposition` が取れない場合は `出願番号_公開番号.zip`（PDF が返れば `.pdf`）に
  フォールバックします。

### 共通

- Windows で使えない `\ / : * ? " < > |`・制御文字は `_` に置換し、末尾の空白とドットを削り、
  予約名（`CON` など）は先頭に `_` を付けます。
- 同名になる組み合わせが複数あるときは `…_2.html` / `…_3.html` のように連番を付け、
  **上書きしません**（大文字小文字は Windows と同様に同一視）。連番は 1 回の実行ごとにリセットされます。
- 先頭が必ず出願番号になるので、ダウンロード後の仕分け（`src/sort_jpo_downloads.bat`）は
  ファイル名先頭の出願番号だけを見れば済みます。
- **「ファイル名の先頭ラベル」を入力した場合だけ**、国内書類が
  `ラベル_出願番号_YYYYMMDD_文書名.拡張子`、ログが `ラベル_出願番号_YYYYMMDD_log.txt` になります
  （OPD は正式形を優先するためラベルの影響を受けません）。
  この場合は先頭が出願番号でなくなるため、`sort_jpo_downloads.bat` の仕分け対象から外れます
  （fail-safe として「動かさない」側に倒れます）。仕分けを使うならラベルは空のままにしてください。
- 廃止した旧規則: v3 までの `出願番号_日付_文書名_種別.拡張子`、v4 初期の
  `出願番号_文書名(日付).拡張子` と `出願番号_OPD_公開番号_モード.zip`。いずれもコード・テスト・
  UI から削除済みです（既にダウンロード済みの旧名ファイルは BAT 側が引き続き仕分けできます）。

## OPD の非同期生成とダウンロード

JPO 側 `doclist.js` の `Doclist.opdDownload()` / `Doclist.__checkOpdBulkStatus()` /
`Doclist.__showDownloadBulkStatus(jsondata, 'opd')` と同じ手順を、公開番号ごとに逐次実行します。

1. 選択した行の `input[name="pubnum"]` から公開番号を取得
2. `URL_OPD_BULK_STATUS` へ `{pubnum, mode}` を POST（`mode` は `individual` / `consolidated` ちょうど）
3. 応答の `status` と `hashkey` を確認
4. `waiting` / `working` の間は `URL_OPD_BULK_STATUS?hashkey=…` を定期的に GET
   （間隔はページの `Doclist.INTERVAL_BULK_STATUS`、無ければ 1000ms）
5. `success` になったら応答の `url`、無ければ `URL_OPD_BULK_DOWNLOAD` の `{hashkey}` を置換した URL を取得し保存
6. `empty` / `error` / タイムアウト / HTTP エラー / 認証切れを区別して表示

**ダウンロードキー（hashkey）は実行ごとに発行されるため、URL をコードに埋め込んでいません。**
API の URL 定数も推測せず、次の順で*実測*します。

1. 実ページのグローバル定数 `URL_OPD_BULK_STATUS` / `URL_OPD_BULK_DOWNLOAD`（`define_url.js` が定義）
2. ページが読み込んでいる共通 JS を同一オリジンで取得し、定数の値を読み取る
3. どちらも取れなければ **OPD 機能を無効化し、理由を画面とログに表示**（推測値では実行しません）

`APIFetch.async_post` / `async_get` がページにあればそれを再利用し（JPO 側のヘッダ処理をそのまま使うため）、
無ければ同一オリジンの `fetch` にフォールバックします（`credentials: same-origin`、`csrftoken` クッキーがあれば
`X-CSRFToken` を付与、JSON が 400/415 のときはフォーム形式で再試行）。

### 状態表示

各公開番号の行に状態バッジを出します（`aria-live="polite"` で読み上げ対象）。

| 内部状態 | 表示 | 色 |
|---|---|---|
| `WAITING` | 待機中 | グレー |
| `GENERATING` | 生成中 | 青（スピナーあり） |
| `DOWNLOAD_STARTED` | ダウンロード開始 | 緑 |
| `NO_TARGET` | 対象なし | 黄 |
| `FAILED` | 失敗 | 赤 |
| `CANCELED` | キャンセル | 橙 |

「ダウンロード開始」は、生成要求が通った時点ではなく**実際に保存を開始した時点**で立てます。
ブラウザからダウンロードの完了は確実に取れないため、「完了」とは表示しません。

他庁公開情報が無い案件（例: `特願2023-170613`）ではエラーにせず、
「利用可能なOPD公開番号はありません」と表示し、国内書類の機能はそのまま使えます。

## 処理開始ボタン

国内書類と OPD を独立に判定します。どちらか一方でも実行可能ならボタンが有効になります。

- 国内書類が 1 件以上選択され、かつ出力形式が 1 つ以上選択されている
- OPD が有効で、OPD 公開番号が 1 件以上選択されている

ボタン表示は `国内6件＋OPD3番号を処理` / `OPD3番号をダウンロード` / `国内6件を処理` のように対象を示します。

## 既知の制約

- **認証セッションが必須**。ログアウト状態や別ブラウザプロファイルでは 401/403 になります。
- **複数ファイルの連続ダウンロードにブラウザの許可が必要**。Chrome / Edge は同一サイトからの複数
  ダウンロードを既定でブロックすることがあります。アドレスバーの通知から「複数のファイルのダウンロード」を
  許可してください。ツール側では各保存の間に約 250ms の間隔を空けています。
- **印刷はポップアップの許可が必要**。ブロックされると「ポップアップがブロックされています」と表示します。
- **PDF は画像ページの結合**。画像を持たない文書は PDF 化できません（印刷から「PDFとして保存」を使用）。
- **ダウンロードの完了は検知できない**ため、OPD の状態は「ダウンロード開始」までしか進みません。
- **OPD の生成待ちは最大 180 秒**。超えた場合は「失敗（生成待ちが上限を超えました）」になります。
- 対象ページの CSP は `script-src 'self'` です。ブックマークレットの実行自体はブラウザが例外扱いにしますが、
  この制約に合わせて実行時コードに `eval` / `new Function` を一切含めていません（テストで検査しています）。
- ページ側 DOM の変更で動かなくなる可能性があります。出願番号は meta →`#lappnum`→「本願番号」欄→
  `data-title`→`data-content-evrika`→URL→`<title>` の順にフォールバックしますが、
  文書行そのものの構造（`tr[data-content-id]` と `td.name` / `td.date`）が変わると収集できません。
- OPD API のリクエスト/レスポンス形式は `doclist.js` の呼び出し方から導いたものです。
  実 API の詳細（POST のボディ形式・成功時の `url` の有無・返るファイルの種別）は
  **JPO の実ページ上でのみ確認できます**。

## ダウンロードの仕分け（`src/sort_jpo_downloads.bat`）

ブラウザのダウンロードフォルダに溜まったファイルを、**直近でダウンロードした出願番号 1 件ぶんだけ**
拡張子別のフォルダへ移動する Windows 用バッチです。`document_downloader` と
`blank_note_printer` の出力をまとめて片付けるために使います。

### 使い方

1. `src/sort_jpo_downloads.bat` をダウンロードフォルダにコピーする
2. ダブルクリック（または `sort_jpo_downloads.bat 特願2022-122252` のように出願番号を指定）

```
sort_jpo_downloads.bat                  … 直近ファイルから出願番号を自動判定
sort_jpo_downloads.bat 特願2022-122252   … 出願番号を明示指定
```

### 仕分け先

```
出願番号
├─ HTML   … .html / .htm
├─ TXT    … .txt
├─ PDF    … .pdf
├─ IMG    … .png / .jpg / .jpeg / .gif / .bmp / .webp
└─ OPD    … .zip
```

実際に該当ファイルがある種類のフォルダだけを作ります（OPD が無ければ `OPD` は作りません）。

### 「直近の出願番号」の決め方

1. フォルダ**直下**の、対象拡張子を持つファイルだけを候補にする
2. 各候補のファイル名**先頭**から出願番号（`特願` / `実願` / `意願` / `商願` + 西暦4桁 + `-` + 連番6桁）を取り出す
3. 出願番号を取り出せた候補のうち、**最終更新日時が最も新しいもの**の出願番号を今回の対象にする
4. **その出願番号で始まる候補だけ**を移動する

引数で出願番号を指定した場合は 3 を飛ばし、指定された出願番号だけを対象にします
（出願番号の形になっていない引数はエラーにして 1 件も移動しません）。

### 新旧の命名にどちらも対応

判定に使うのは「ファイル名先頭の出願番号」と「拡張子」だけで、日付や文書名の位置は見ません。
そのため、移行期間中に混在する次のすべてを同じ出願番号として扱えます。

| 形式 | 例 |
|---|---|
| 新命名（国内書類） | `特願2022-122252_20260602_手続補正書（自発・内容）.pdf` |
| 旧命名（国内書類） | `特願2022-122252_手続補正書（自発・内容）(20260602).pdf` |
| 旧命名（画像） | `特願2022-122252_図面(20220729)_p004.png` |
| OPD | `特願2022-122252_EP4312460A1.zip` |
| blank note | `特願2022-122252_note.pdf` |

### 安全策

- **対象出願番号と一致しないファイルは移動しません。** 別出願のファイルはその場に残り、
  最後に `KEEP: left in place (other applications): …` として一覧表示します。
- **出願番号を読み取れないファイルは移動しません**（fail-safe）。無理に推測しません。
- **対象拡張子以外は移動しません**（`.docx` / `.exe` / `.crdownload` などはそのまま）。
- **BAT 自身は移動しません。**
- **フォルダ直下だけ**を見ます（`-Recurse` しない）。既に仕分け済みの `特願…\` の中は再処理しません。
- **上書きしません。** 移動先に同名があれば `filename_2.pdf` / `filename_3.pdf` … を使います。
- 日本語ファイル名（`特願` / `手続補正書` / `（自発・内容）` / `図面`）は UTF-8 のまま壊さずに扱います。
- 旧版にあった「直近 1 時間のファイルを全部まとめて移動」は**廃止**しました。時間ではなく出願番号で
  絞るほうが誤移動しにくく、かつ数時間前にダウンロードした同一出願のファイルも取りこぼさないためです。
- 旧版の `HTML_INI` フォルダ名も廃止し、`HTML` に統一しました。

### 実装メモ

BAT の本体は末尾に埋め込んだ PowerShell です（cmd は `exit /b` でそこへ到達しません）。
1 ファイルのまま可読な PowerShell を書くための構成で、`powershell -Command` の 1 行に
すべてを詰め込む旧版の書き方はやめています。環境変数 `JPO_SORT_NOPAUSE` を定義すると
最後の `pause` を省略します（自動テスト用）。

動作確認は `tests/sort-bat.test.js` が OS の一時フォルダに実験用のダウンロードフォルダを作って行うので、
**本物のダウンロードフォルダは使いません**。

制約: Windows 専用（`cmd.exe` + Windows PowerShell 5.1 以降）。組織のポリシーで PowerShell が
ConstrainedLanguage モードに固定されている環境では、埋め込みスクリプトの読み込み
（`[scriptblock]::Create`）が拒否されることがあります。

## 開発

- 正本は `src/bookmarklet/collector.js`（手編集ソース。自動生成バナーなし＝編集してよい印）。
- `collector.js` を直したら **必ず** 1 行版を作り直してください:

  ```
  node document_downloader/scripts/build-bookmarklet.js
  ```

  1 行化は「コメント除去・改行削除」ではなく最小 URL エンコード（`%`→`%25`、`#`→`%23`、改行→`%0A`）で
  行うため、`collector.js` と `collector.bookmarklet.js` のロジックは構造的にずれません。
  ずれていれば `tests/build.test.js` が失敗します。
- `collector.js` の構成（節番号で責務を分離）:
  1 文字列ユーティリティ / 2 ページ種別の検出 / 3 出願番号の取得 / 4 国内文書行の収集 /
  5 OPD 行の収集 / 6 URL 解決 / 7 ファイル名生成 / 8 HTML→テキスト / 9 CORE 公開 /
  10 通信層 / 11 文書内容の取得 / 12 形式別の変換 / 13 ダウンロードキュー /
  14 OPD 生成状況の監視 / 15 UI / 16 main
- 1〜9 節（`CORE`）は DOM 非依存または `Document` を引数に取る純粋処理で、Node のテストから
  `require()` して直接検証できます（ブラウザでは `window.__JPO_DOC_COLLECTOR_CORE__` にも出ます）。
